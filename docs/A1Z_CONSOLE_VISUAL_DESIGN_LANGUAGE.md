# A1Z Console 视觉设计语言

> **Calm Precision / 克制而精密**
>
> 状态一眼看清，操作自然安静，危险永远明确。

- 状态：视觉方向定稿，可作为 GUI 改版实施基线
- 适用范围：`console/qml/A1ZConsole/` 的桌面控制台
- 基准界面：2026-07-31 当前 QML，1560 × 940
- 默认外观：Apple 风格浅色界面；深色只保留给相机、日志等内容视口
- 本文只定义图形风格、视觉层级和交互外观，不改变控制语义、安全逻辑或 SDK 能力

## 1. 设计结论

A1Z Console 采用一种受 Apple 设计原则启发、但为机器人控制场景重新约束的浅色设计语言。视觉基底直接采用 Apple 官方系统背景、灰阶和语义色中的具体 sRGB 值，但不照搬 macOS 窗口，也不追求玻璃拟态；“苹果感”主要来自以下四件事：

1. **内容优先**：数据、状态和当前任务比容器更醒目。
2. **层级克制**：主要靠留白、字号和明度建立层级，少靠描边、渐变和色块。
3. **焦点唯一**：一个操作阶段只有一个主按钮，其他动作主动退后。
4. **反馈可信**：颜色有稳定语义，运动、安全和故障状态不含糊。

最终气质应是：

- 简约，但不空洞；
- 大气，但不夸张；
- 精密，但不拥挤；
- 专业，但不像传统工控组态屏；
- 安静，但危险操作仍足够醒目。

## 2. 当前视觉问题

当前界面已经具备较完整的信息架构，主要问题不是功能布局，而是视觉语言同时说了太多种“方言”。

| 现状 | 视觉影响 | 改版原则 |
| --- | --- | --- |
| 窗口渐变、半透明面板、玻璃高光、卡片描边同时存在 | 容器比内容更抢眼，画面显得碎 | 改为纯色中性表面，用明度差和间距分层 |
| 顶栏同时出现蓝、红、橙和多枚描边胶囊 | 所有状态都在报警，没有主次 | 正常状态降噪，只让异常状态获得语义色 |
| 导航使用 `◈`、`✣`、`◎`、`◇`、`≋` 等字符 | 字重、尺寸和基线不一致，显得临时 | 使用一套 16–18 px 单色线性 SVG 图标 |
| 普通按钮大量使用明显描边，主次动作外形接近 | 页面按钮密度高，动作优先级不清 | 建立 Primary、Secondary、Quiet、Danger 四级按钮 |
| `ComboBox`、`SpinBox` 等保留 Qt 默认外观 | 尺寸、圆角和交互状态与自绘控件割裂 | 所有基础控件使用统一的浅色包装组件 |
| 卡片内部继续嵌套色块、条纹、胶囊和强调色竖线 | 信息被切成过多小盒子 | 卡片内部优先使用留白和细分隔线 |
| 青色、紫色、绿色也参与装饰 | 色彩没有稳定语义 | 蓝色只表示交互；绿、橙、红只表示状态 |
| 多处固定高度在无数据时留下大块“盒内空白” | 不是有意留白，而像内容缺失 | 普通卡片随内容收缩，仅预览和日志保留弹性视口 |
| 离线状态在胶囊和红色错误文本中重复出现 | 同一问题争抢两次注意力 | 顶栏给摘要，详细错误进入单一横幅或日志 |

## 3. 核心设计规则

### 3.1 少画盒子

- 页面背景、一级表面、二级表面最多形成三层明度。
- 一级卡片默认无描边；只有相邻表面难以区分、获得键盘焦点或处于告警状态时才出现边框。
- 不在卡片顶部绘制“玻璃高光”。
- 不使用全窗口渐变、发光、彩色阴影或拟物质感。
- 不在一张卡片里继续堆叠多张完整卡片；次级分组使用标题、间距或 1 px 分隔线。

### 3.2 少用颜色

正常页面只允许同时出现：

- 白色与 Apple 系统灰；
- 一个交互蓝色；
- 当前确实存在的语义状态色。

颜色不能用来区分普通功能类别。例如相机、轨迹、夹爪不再分别使用青、紫、绿作为装饰。颜色必须能够回答“这是可操作焦点，还是系统状态？”

### 3.3 少做强调

- 每个页面或流程步骤最多有一个实心蓝色主操作。
- 普通工具动作使用中性按钮或 Quiet 按钮。
- 绿色不用于普通操作按钮；绿色只表达“已连接、通过、完成、处于安全范围”。
- 红色只用于立即运动风险、急停、不可逆操作、故障和失败。
- 标题不依赖全大写与过大字距。产品名可以保留短小大写，中文标题不增加字距。

### 3.4 层级必须在灰度下仍然成立

将截图转成灰度后，仍应能分辨：

1. 页面标题；
2. 当前状态或核心数据；
3. 当前主操作；
4. 分组标题；
5. 次要说明。

如果去掉颜色就看不出主次，说明结构、字号或留白还没有设计好。

## 4. 颜色系统

### 4.1 官方来源与固定策略

颜色基线来自以下 Apple 官方资料：

- [Apple Human Interface Guidelines — Color](https://developer.apple.com/design/human-interface-guidelines/color)：系统色、系统灰和语义用法；
- [Apple 官方 UIKit 规格示例](https://developer.apple.com/support/downloads/storekit-external-purchase-modal-sheet.pdf)：`SystemBackground #FFFFFF`、`Secondary System Background #F2F2F7`、`SystemBlue #007AFF` 等具体值；
- [Apple Design Resources](https://developer.apple.com/design/resources/)：官方平台 UI Kit、字体和图标资源入口。

Apple 官方建议在 Apple 平台上使用动态系统色，而不是硬编码色值。A1Z Console 是运行在 Linux/Qt 上的跨平台控制台，无法调用 UIKit、SwiftUI 或 AppKit 的动态颜色 API，因此采用以下策略：

1. 在 `Theme.qml` 中按语义命名，而不是按外观命名；
2. 固定一份 **2026-07-31 Apple Light sRGB 参考快照**；
3. 页面只引用 token，不直接写 Apple 色值；
4. Apple 官方色值更新时，只评估和修改 Theme，不逐页改色；
5. 不声称这些固定值具备 Apple 系统原生的动态外观、材质或辅助功能适配能力。

Qt/QML 采用 `#AARRGGBB`；下表同时给出常见 `#RRGGBB`，方便设计评审。

| `logCanvas` | `#FF1C1C1E` | Apple System Gray 6 Dark | 长日志视口 |

补充规则：

- 白色不是“所有地方都白”。`canvas #F2F2F7` 负责分组，`surface #FFFFFF` 负责承载内容。
- `textPrimary` 与白色背景对比度为 21:1。
- `textSecondary` 与白色背景对比度约 5.2:1，可承载普通辅助正文；`textTertiary` 只用于注释、单位和非关键空状态。
- `#007AFF` 用于图标、链接、焦点和选中；小字号白字主按钮使用高对比度变体 `#1E6EF4`。
- `#FF383C` 用于状态图标和文本；白字危险按钮使用 `dangerFill #E9152D`。
- 绿色和橙色不承载白色小字按钮，避免对比不足。
- 柔和语义底色统一使用对应颜色 10–12% 透明度，不另外发明新色。
- 禁止在页面文件中硬编码颜色；所有颜色从 `Theme.qml` 获取。
- 相机、点云和日志允许使用深色内容画布，但外围应用外壳保持浅色。

## 5. 字体与排版

### 5.1 字体

字体优先级：

1. macOS 使用系统 UI 字体；
2. Linux 中文使用 `Noto Sans CJK SC`；
3. 拉丁字符可选 `Inter`，但不得为了外观额外打包未确认授权的 Apple 字体；
4. 实时数值、关节角和日志使用等宽字体，并启用等宽数字观感。

不要依赖粗体制造层级。主要使用 Regular、Medium、Semibold 三档。

### 5.2 字号

| 角色 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| Page title | 24 / 30 | 600 | 页面标题 |
| Section title | 17 / 24 | 600 | 卡片和主要分组 |
| Body | 14 / 20 | 400 | 正文和说明 |
| Label | 13 / 18 | 500 | 字段名、按钮、表头 |
| Caption | 12 / 16 | 400 | 单位、次级状态、时间 |
| Data | 14 / 20 | 500 | 角度、速度、力矩、温度 |

规则：

- 中文正文不增加字距。
- 产品名 `A1Z Console` 不再使用过强的全大写和 0.8 px 字距。
- 单位颜色低于数值一个层级，例如 `0.50` 为主文本、`rad/s` 为次文本。
- 数字列右对齐，小数位稳定，避免遥测刷新时列宽跳动。
- 日志可以使用 12–13 px 等宽字体，但正文不要滥用等宽字体。

## 6. 间距、尺寸与形状

### 6.1 间距

统一使用 4 px 基准网格：

| Token | 值 | 用途 |
| --- | --- | --- |
| `space1` | 4 | 图标内部、紧凑元素 |
| `space2` | 8 | 同组控件 |
| `space3` | 12 | 紧凑卡片、表格行 |
| `space4` | 16 | 默认卡片内边距 |
| `space5` | 24 | 大分组间距 |
| `space6` | 32 | 页面章节间距 |

废除当前不在网格内的 7、9、10、11、13、22 等随意间距；确有视觉校正需要时应在组件内部说明原因。

### 6.2 圆角

| 角色 | 圆角 |
| --- | --- |
| 小标签、紧凑状态 | 6 px |
| 按钮、输入框 | 8 px |
| 卡片 | 12 px |
| 顶栏、侧栏等大型外壳 | 16 px |
| 胶囊 | 仅状态标签可使用高度的一半 |

不要让所有元素都变成胶囊。苹果式简洁来自比例和层级，不是来自无限圆角。

### 6.3 控件高度

- 默认按钮和输入框：40 px；
- 紧凑表格工具按钮：36 px；
- 主操作、危险操作：44 px；
- 左侧导航行：44 px；
- 可点击区域最小高度：36 px；
- 图标：导航 18 px，按钮 16 px，线宽统一约 1.5 px。

## 7. 组件规范

### 7.1 Button

| 类型 | 外观 | 使用场景 |
| --- | --- | --- |
| Primary | `accentFill` 实心底、白字、无描边 | 当前阶段唯一的推荐动作 |
| Secondary | `control` 底、主文本、无常驻强描边 | 普通动作 |
| Quiet | 透明底；悬停时出现 `control` | 工具栏、表格内、低频辅助动作 |
| Danger | `dangerFill` 实心底、白字 | 急停、校零、实际执行等高风险动作 |

交互状态：

- Hover：表面明度提升一级，100–140 ms；
- Pressed：明度降低约 8%，不做明显缩放；
- Focus：2 px `accent` 焦点环，不能只靠颜色变亮；
- Disabled：内容与表面降至约 38% 感知强度，不响应 Hover；
- Busy：保留按钮尺寸和文字区域，显示小型进度指示，避免布局跳动。

禁止：

- 用绿色表示“可以点击”；
- 普通按钮使用彩色描边；
- 同一卡片出现多个实心蓝按钮；
- 靠按钮颜色区分 SIM 和 REAL 的全部语义。

### 7.2 输入控件

`TextField`、`TextArea`、`ComboBox`、`SpinBox`、`Slider` 必须全部自定义。浅色界面也不能直接保留 Qt Basic 原生控件，因为其尺寸、箭头、焦点和禁用状态与自绘组件不一致。

统一规则：

- 40 px 高，8 px 圆角，`control #F2F2F7` 背景；
- 默认无强描边，悬停时轻微提亮；
- Focus 时出现 2 px 蓝色焦点环；
- 标签放在控件上方或左侧，不能只依赖 placeholder；
- 单位作为稳定后缀显示，不混进可编辑数值；
- 错误状态使用红色边框和一行明确原因，不只把文字染红；
- `SpinBox` 的减号、值、加号组成一个完整的浅灰分段控件，不再出现三块互相割裂的方框；
- `Slider` 的未激活轨道保持中性，拖柄不需要阴影或发光。

建议增加统一组件：

- `AppTextField.qml`
- `AppTextArea.qml`
- `AppComboBox.qml`
- `AppSpinBox.qml`
- `AppSlider.qml`
- `SegmentedControl.qml`

### 7.3 Card

卡片是内容分组，不是装饰。

- 使用 `surface` 或 `surfaceRaised`；
- 12 px 圆角、16 px 默认内边距；
- 默认不绘制顶部高光；
- 默认不绘制完整描边；
- 卡片标题与正文间距 12 px；
- 普通卡片高度随内容变化；
- 相机预览、日志、轨迹表等视口可以填充剩余空间；
- 空状态只保留一句说明和一个必要动作，不再嵌套空框。

当前 `GlassCard.qml` 可以先保留文件名以降低迁移成本，但视觉上应成为普通的 `SurfaceCard`。

### 7.4 Status

状态分为五级：

| 级别 | 表达 |
| --- | --- |
| Neutral | 灰色圆点 + 次文本 |
| Info | 蓝色圆点 + 主文本 |
| Success | 绿色圆点 + 主文本 |
| Warning | 橙色圆点 + 主文本，必要时柔和底色 |
| Critical | 红色图标/圆点 + 主文本，必要时横幅 |

规则：

- 正常状态不需要彩色描边胶囊。
- 顶栏状态应短：`控制离线`、`RGB-D 在线`、`遥测 24 ms`。
- 详细错误只出现一次：顶栏下方横幅用于当前问题，日志保存完整内容。
- 状态必须同时包含文字或图标，不能只靠红绿颜色。
- “未连接”在当前任务不要求连接时应为 Neutral，而不是 Critical。

建议将 `StatusPill.qml` 演进为 `StatusIndicator.qml`，胶囊底只在 Warning/Critical 或需要强分组时出现。

### 7.5 Navigation

- 左侧栏保持 176–190 px，导航行高 44 px。
- 使用同一套 18 px 线性 SVG 图标；禁止继续使用 Unicode 几何字符。
- 未选中项透明，文字为 `textSecondary`。
- Hover 使用 `control` 柔和底色。
- 选中项使用 `accentSoft`，图标为 `accent`，文字为 `textPrimary`。
- 不额外绘制左侧彩条、描边和阴影。

建议图标语义：

| 页面 | 图标语义 |
| --- | --- |
| 运行总览 | gauge / activity |
| 手动操控 | sliders / move |
| 感知检查 | camera / scan |
| 自动抓取 | target / aperture |
| 示教与回放 | record / playback |
| 运行配置 | command / settings |
| 诊断与维护 | waveform / tools |

图标可采用授权清晰的开源线性 SVG 集，并在仓库中固定具体 SVG，避免系统字体差异。

### 7.6 表格与实时数据

- 表头使用 12–13 px Medium、`textTertiary`。
- 数据行高 40–44 px。
- 默认不使用完整单元格边框，只保留横向分隔或非常轻的斑马纹。
- 标签左对齐，数值右对齐，单位列宽固定。
- 正常数值保持中性；只在越界时使用语义色。
- 关键变化可以短暂使用 300 ms 柔和底色提示，禁止持续闪烁。

### 7.7 横幅与通知

新增 `InlineBanner.qml`，用于当前需要用户理解的问题：

- Info：蓝色图标 + 中性表面；
- Warning：橙色图标 + 低透明橙色底；
- Critical：红色图标 + 低透明红色底；
- 一行摘要，可展开详情；
- 同一时刻页面顶部最多显示一个最高优先级横幅。

顶栏不再同时堆叠状态胶囊和一整行红色异常文本。

```text
│          │                               │ 软件急停       │

```

颜色层级：

- 顶栏、左侧导航和右侧安全栏使用 `surface #FFFFFF`；
- 中央页面底色使用 `canvas #F2F2F7`；
- 内容卡片回到 `surface #FFFFFF`；
- 仅弹层使用微弱阴影，常驻卡片不制造悬浮感。

尺寸建议：

- 外层边距：12 px；
- 顶栏高度：56 px；
- 左侧栏：176–190 px；
- 安全侧栏：272 px，保持稳定位置；
- 栏间距：12 px；
- 页面标题与首张卡片间距：12 px；
- 1220 × 760 为紧凑验收尺寸，1560 × 940 为标准验收尺寸。

顶栏调整：

- 品牌名改为 `A1Z Console`，降低字重和字距。
- SIM / REAL 改为一个分段控件，不再做两个竞争的彩色按钮。
- 连接、相机和遥测显示为简短状态摘要。
- 当前错误进入横幅；顶栏仅保留红色问题标记。
- “刷新”使用 Quiet 按钮，避免和主任务竞争。

## 9. 页面级改版方向

### 9.1 运行总览

- 关节状态表是第一视觉焦点，减少卡片边框和行色块。
- 相机预览与链路状态构成第二分组。
- 移除相机、轨迹 MetricTile 的青色和紫色装饰竖线。
- 正常错误码使用中性文本；只有非零错误码变红。
- 无画面时使用简洁空状态，不再强调黑色内框。

### 9.2 手动控制

- 保留“读取 FK → 单关节点动 → 末端点动 → 夹爪”的任务顺序。
- 负向步进和正向步进做成对称的分段按键组，减少每行三个描边矩形的割裂感。
- 目标值输入使用统一浅灰字段，读回值与软限位作为次文本。
- 当前可执行的唯一推荐动作使用 Primary；其余点动按钮保持中性。
- 运动相关控件不做弹跳、缩放或夸张动画。

### 9.3 自动抓取

- 保留“1 计算、2 审阅、3 执行”的三阶段结构，这是当前最清晰的信息骨架。
- 只有当前阶段使用 Raised 表面；未开始阶段降低明度。
- 计划安全状态在审阅标题附近显示，不重复多个胶囊。
- “开始计算”是计算阶段主操作；“执行计划”是明确的危险操作。
- 第 3 阶段无计划时随内容收缩，避免大块空卡片。

### 9.4 手动操控与运行配置

- 顶层只保留行为入口；手动操控内部按“运动与定位 / 末端工具”切换，不再按 SDK
  模块来源拆页。服务参数只进入运行配置，相机只进入感知检查。
- 模式、目标编辑和物体交互保持独立面板，降低每个普通动作的按钮存在感。
- 预置动作使用 Quiet 或紧凑 Secondary 按钮，不形成一整面描边按钮墙。
- “启动服务”可以是当前主操作；“停止服务”只有服务运行时才显示为明确操作，但不默认占用鲜红色。
- 补偿系数、采样率、回放倍率全部换成统一浅色控件。
- 去除绿色普通操作按钮，例如“零力录制”不应因为是功能动作而使用成功色。

### 9.5 诊断与维护

- 左侧按“预检、ROS 2、CAN/电机、校零”组织，卡片之间用大间距而不是强描边。
- 普通诊断动作使用 Quiet/Secondary；“运行预检”作为唯一主操作。
- 校零区使用独立 Warning/Critical 区块，只有最终确认按钮使用红色。
- 日志视口使用专用深色表面，工具按钮退为 Quiet。
- 暂停跟随、清空等工具不应与预检主操作同权重。

## 10. 运动与安全的视觉不变量

改版不能为了“好看”削弱安全表达：

- 软件急停始终固定在右侧栏底部，不随页面滚动。
- 急停按钮使用唯一、稳定的红色实心样式，最小高度 44 px。
- 急停区不再同时使用红色外框、红色标题和红色内层按钮制造三重强调；一个红色主按钮加清晰说明即可。
- REAL 状态使用 `REAL 真机` 文本、设备状态和必要警示共同表达，不能只靠红色。
- 实际运动、校零、真实抓取执行必须在按钮文字中说明动作，不使用模糊的“确定”。
- 运动锁、身份不匹配、遥测陈旧等禁用原因应在操作附近明确显示。
- 颜色不是唯一安全线索；始终配合文字、图标或位置。
- 不确定锁解除入口保持受保护，不因为视觉简化而降低确认门槛。

## 11. QML 落地映射

| 文件 / 组件 | 改版动作 |
| --- | --- |
| `Theme.qml` | 替换为本文 token；补全表面、焦点、控件状态和语义柔和底色 |
| `Main.qml` | 去除窗口渐变；简化顶栏；SIM/REAL 使用分段控件；错误改为单一横幅 |
| `GlassCard.qml` | 去掉顶部玻璃高光和默认强描边，保留迁移兼容 |
| `AppButton.qml` | 实现 Primary / Secondary / Quiet / Danger 和统一 Focus、Disabled、Busy 状态 |
| `NavButton.qml` | 使用统一 SVG 图标，移除 Unicode glyph |
| `StatusPill.qml` | 降低正常状态的胶囊感，逐步演进为 `StatusIndicator` |
| `MetricTile.qml` | 移除装饰性彩色竖线，仅在真实状态异常时使用语义色 |
| `SafetyRail.qml` | 改为扁平分组；SpinBox、Slider 统一样式；急停保留固定位置 |
| 各 Page QML | 删除硬编码颜色，减少固定高度与嵌套卡片，按本文主次按钮规则调整 |

推荐实施顺序：

1. 先完成 Theme 和全部基础控件，不直接逐页调颜色；
2. 再改应用外壳、导航、顶栏和安全侧栏；
3. 按“运行总览 → 手动控制 → AnyGrasp → SDK 功能 → 诊断”逐页迁移；
4. 最后统一空状态、日志、相机预览和细节动效；
5. 每个阶段同时保留 1220 × 760 与 1560 × 940 离屏截图做视觉回归。

## 12. 验收清单

视觉改版完成时应满足：

- [ ] 窗口没有全局渐变、玻璃高光和彩色阴影。
- [ ] 页面正常状态只使用白色、Apple 系统灰和一个 System Blue。
- [ ] 绿、橙、红只表达稳定的语义状态。
- [ ] 所有颜色来自 `Theme.qml`，页面中没有硬编码色值。
- [ ] 所有 Qt 输入控件都已统一定制，不残留 Qt Basic 原生外观。
- [ ] 导航图标来自同一套 SVG，不再使用 Unicode 几何字符。
- [ ] 每个卡片或流程阶段最多一个 Primary 按钮。
- [ ] 普通操作不使用绿色，危险操作不使用含糊文案。
- [ ] 卡片默认不依赖完整描边建立层级。
- [ ] 页面没有由固定高度造成的无意义大块盒内空白。
- [ ] 正文和关键状态达到至少 4.5:1 的对比度。
- [ ] 键盘焦点始终可见，禁用原因可以理解。
- [ ] 状态不只依靠颜色表达。
- [ ] 软件急停在所有页面位置固定、样式唯一。
- [ ] 1220 × 760 下控件不重叠，1560 × 940 下布局不松散。
- [ ] 将截图转为灰度后，页面标题、关键数据、主操作和危险状态仍有明确层级。

## 13. 一句话评审标准

每次新增或修改视觉元素时，只问三个问题：

1. **它是在帮助用户看清内容，还是只是在装饰容器？**
2. **它是否抢走了比自己更重要的操作或状态的注意力？**
3. **去掉这个颜色、描边或圆角，信息是否依然成立？**

如果一个元素不能通过这三问，就继续做减法。
