# A1Z Control Console

Qt 6 / QML 桌面控制台，参考 `duojin_l1w_control_gui` 的控制器与界面分层，
但针对机械臂改为离散事务模型：

- 控制服务是唯一官方 SDK / CAN 所有者，GUI 不创建第二个 `ArmRobot`；
- `sim` 固定连接 `isaacsim@127.0.0.1:37103`，`real` 固定连接
  `socketcan@127.0.0.1:37104`；
- 所有运动按钮在工作线程的单队列内执行，繁忙期间不会继续排队；
- 软急停使用独立高优先级通道，不会排在阻塞式运动之后；状态回读也不占用运动锁；
- 每次运动前重新读取 `info` 并核对后端身份；
- 运动请求没有自动重试。请求已发出后若响应丢失、截断、JSON/字段无效，或服务
  报告“已提交但反馈未到位”，GUI 都按结果不确定锁定运动；只有响应同时声明
  `ok=false` 和 `execution_state=rejected` 才视为执行前确定拒绝。现场确认只会
  触发重新核验，必须在同一 profile 收到一轮新鲜关节遥测后才真正解除；
- 关节点动每次读取最新角度后只发送一个 `move`；服务端随后只轮询 SDK
  `get_joint_pos()`，达到容差才向界面报告完成；
- 机械臂页的关节目标和夹爪页的开度目标是稳定的本地草稿，不会被周期遥测覆盖或重建；
  未发送的绝对关节目标会锁住增量点动，未发送的夹爪开度会锁住夹持/释放，
  必须先发送或明确放弃，空白或越界关节值不能发送；
  操作结果固定显示到下一次操作或人工关闭，后台健康遥测不会把它一闪而过地清掉；
- G1Z 开度控制独立于机械臂的“位置保持 / 零力漂浮”模式，只受控制循环、
  急停和夹爪自由拖动状态约束；发送目标后以真实夹爪反馈到位为完成条件；
- 零力补偿 factor 是 SDK 构造参数。界面允许手动配置，但“应用”会重启控制
  服务并以位置保持模式恢复，不在运行中的控制循环里热切换扭矩比例；
- 末端点动使用官方 Pinocchio FK/IK，保留 2° 关节裕量，并拒绝超过 15° 的
  单步 IK 分支跳变；Base/Tool 变换与完整 SDK 能力映射见
  `docs/A1Z_CONSOLE_SDK_COVERAGE.md`；
- AnyGrasp 分为“只计算并审阅”和“执行当前已审阅计划”，两者不是同一个按钮。
- 示教录制是全局持久状态：开始后只开放“停止并保存”、遥测、相机与软急停；
  停止时恢复位置保持和夹爪控制。轨迹按后端隔离并记录来源，SIM 轨迹不能在
  REAL 回放；若录制期间端点丢失，界面保留“状态待确认”锁，直到重新连接取得
  服务权威状态，或显式放弃未保存录制并确认停止服务；“停止并保存”属于录制
  收尾而不是运动，即使控制循环已故障、停止或软急停锁定也保留该出口；
- RGB-D 预览统一订阅配置选定的 ROS 主题；GUI 不直接打开 USB 或
  `/dev/video*`，仿真与真机使用同一条相机桥协议。

## 界面架构

- `Main.qml` 只管理窗口生命周期，并组合顶部状态、持久反馈和工作区；
  导航、页面栈和安全栏由 `ConsoleWorkspace` 统一编排。
- 导航使用 `overview`、`manual`、`vision`、`grasp` 等行为路由，不再用页面序号，
  也不按机械臂、夹爪、SDK、ROS 或算法包来源暴露顶层分类。
- 页面使用持久 `StackLayout`，因此未发送的关节、夹爪、重力系数和任务输入
  不会因普通切页无提示丢失；高开销日志绑定在诊断页隐藏时断开。
- 工作区汇总各页面的未发送草稿；草稿存在时 Real/Sim 切换保持锁定，并在
  对应页面提供发送、重新载入或“放弃修改”的明确出口。
- 草稿锁按设备资源传播，而不是只作用于当前页面：未发送的机械臂/夹爪目标会
  同时锁住模式切换、预置动作、抓取执行、示教、服务启停和会改变设备状态的
  诊断入口；未应用补偿参数会锁住侧栏启动/重启。状态查看、遥测刷新和急停不受阻。
- 功能按操作性质划分：手动操控、感知检查、自动抓取、示教与回放、运行配置和
  诊断维护。手动操控内部再按“运动与定位 / 末端工具”切换；实现来源只保留在
  Controller 与适配层内部。
- `ArmControlPage` 只组合模式、末端姿态、关节、笛卡尔和预置动作面板；
  关节草稿状态由 `JointControlPanel` 维护，重复行由稳定的
  `JointControlRow` 展示。顶层只保留工作区所需的草稿别名和兼容方法，
  不再同时持有列表模型、编辑状态和运动触发逻辑。
- `GripperControlPage` 只维护回读与目标草稿同步；模式选择、开度编辑和物体交互
  分别由无 Controller 依赖的面板通过信号表达意图，避免 UI 组件直接绑定 SDK 命令来源。
- `GraspTaskPage` 只组合计算输入、计划审阅和执行确认三个功能面板；
  轨迹行也是独立委托组件。危险执行短语由执行面板所有，任何断连、
  遥测过期、急停、模式或草稿变化使执行资格失效时都立即清空，
  恢复后必须重新表达当前执行意图。
- 所有纵向滚动页使用统一 `PageScrollView`，内容宽度取
  `availableWidth` 并禁用水平滚动，纵向滚动条出现时不会遮住右缘控件。
- 机械臂、夹爪、重力参数各自维护草稿，工作区统一汇总跨 profile 的切换锁；
  控制服务、任务和设备命令由独立 `InteractionPolicy` 按能力和资源做全局仲裁，
  QML 不再共用含糊的 `exclusiveTaskEnabled` 或把所有设备操作套进机械臂运动门槛。
- 外部进程任务显式声明“只读任务 / 在线设备 / 离线设备 / 录制恢复”访问方式，
  以及机械臂、夹爪、标定、服务或传输资源影响；失败是否进入结果不确定锁、
  是否暂停遥测、是否允许中止和完成后失效哪类草稿都由该契约决定，不再从
  脚本来源或任务名称推断。
- 抓取执行声明为“臂夹协同运动”，同时满足位置保持与夹爪开度控制才会放行；
  只计算和 dry-run 仍是普通计算任务，不借用设备运动门槛。
- Controller 构造不会启动网络轮询；QML 根对象成功加载后由应用显式调用
  `startMonitoring()`。关闭是幂等的，迟到的 worker 回调不会再触碰 Qt 对象。
- 外部脚本、容器和 ROS 任务的 `QProcess`、进程组取消、环境注入、合并输出与
  强制收尾由独立 `ProcessTaskRunner` 持有；Controller 只做能力准入、用户反馈
  和任务结果到设备资源状态的投影，QML facade 不暴露进程实现细节。退出码与
  领域结果分开：计划/预检解析可以把退出码 0 最终解释为 warning 或 error，
  Controller 只广播一次审阅后的结果。
- RGB-D 桥的 profile 隔离、轮询节奏、预览帧、请求互斥和工作线程生命周期由
  独立 `CameraCoordinator` 持有；Controller 只代理稳定的相机属性，并把显式
  相机操作结果投影到全局反馈。相机状态使用独立通知，每秒预览轮询不会再
  唤醒八个常驻页面的全局策略绑定；一次全局状态转换也复用同一份不可变策略快照。
  旧 profile 的迟到结果不会覆盖当前视觉状态。
- 遥测和相机协议客户端通过共享的可取消 socket 所有权组件管理在途
  `connect/recv`；切换 profile 或关闭控制台会主动 `shutdown/close` 当前 socket，
  名称解析也通过可取消等待隔离，NSS/DNS 卡住不会再阻止 Python 进程退出；
  全局只允许一个解析 worker，持续的解析故障不会随轮询无限累积线程。
  worker 在登记客户端时复验 profile 代际，关闭“已创建但尚未登记”的切换空窗。
  工作线程仍只向 Python 结果队列写入，不在 Qt 对象销毁期间发送迟到信号。
- `TelemetryCoordinator` 独立持有只读协议通道、700 ms 轮询、profile 代际和
  遥测年龄时钟；长运动不会再因为与命令共用执行队列而人为停止状态更新，只有
  明确声明阻断遥测的任务会暂停轮询。200 ms 年龄变化使用独立通知信号，不会
  唤醒全部页面；关节、夹爪、计划、日志和操作反馈也各自使用独立信号。机械臂
  姿态变化通过稳定语义事件通知草稿失效，不依赖可翻译的中文操作文案。
- `DeviceCommandExecutor` 独立持有普通设备命令和软急停两条执行通道，统一维护
  命令序列、profile 代际和急停 safety epoch。普通命令保持单路串行，软急停不
  等待阻塞运动；急停提交前已经开始的命令即使随后成功返回，也不会再覆盖界面
  中已经确认的急停状态。所有 worker 结果都经 GUI 线程队列投影。
- `PlanSessionCoordinator` 按一次抓取任务的真实生命周期维护目标、profile、
  计算产物、安全结论和执行契约；通用 Controller 不再解析计划或拼装执行命令。
  无效视觉后端会显式拒绝，计算产物必须位于本次会话目录内，安全未通过的计划
  只能做不发送运动的演练，不能进入真实执行。UI 读取的当前计划状态在
  会话转换时维护，不在属性 getter 中反复访问文件系统；每次真正执行前仍会
  重新核对文件存在性、会话路径和审阅时的 SHA-256，执行脚本再复验同一哈希，
  并独立要求物理执行计划的五项安全检查、有限关节值、正超时和完整有序的
  `pregrasp → approach → lift → retreat` 阶段；执行前还会用已核验后端返回的
  六轴软限位逐段复查目标，避免审阅后文件被替换、伪造安全标记或绕过 GUI。
- `DraftLockCoordinator` 将常驻页面中的机械臂目标、夹爪开度和启动配置草稿按
  受影响资源汇总。按钮禁用只是第一层提示；Controller 的设备命令、计划执行、
  服务和传输任务会再次按资源契约拒绝冲突操作，提交本草稿及急停恢复出口使用
  显式豁免。草稿变化使用独立通知，不会触发遥测同步把编辑值清掉。
- `KinematicsCommandAdapter` 独立封装 FK/IK helper 的容器命令、profile 环境、
  JSON 契约和“请求可能已发送”的歧义判定；Controller 只校验界面动作、提交
  命令并投影姿态结果，不再直接运行子进程。
- `TeachingSessionCoordinator` 独立维护示教录制的 profile、服务权威状态、
  保存摘要、端点丢失后的孤立会话锁和输入边界。端点离线不会清空录制所有权；
  QML 分别显示“录制中”“状态待确认”“轨迹已保存”，不再从按钮可用性猜状态。
- `DiagnosticsSessionCoordinator` 独立维护 profile 作用域的预检请求、显式状态、
  结果契约和维护操作目录。预检退出码为 0 仍须校验 profile、检查项和失败计数；
  CAN 检查与会影响设备状态的离线维护分别使用不同能力门槛。诊断页按预检、
  ROS 链路、设备维护和日志四种功能拆成独立面板，不再按脚本来源堆叠逻辑。
- 诊断日志使用有界增量模型，只为新增行创建或复用委托，不再按 80 ms 周期
  重排整份千行文本；最大行宽由模型稳定维护，不会随着虚拟委托创建/回收而跳动；
  暂停跟随只影响滚动，不中断后台日志收集。

## 启动

从仓库根目录运行：

```bash
./scripts/run_a1z_console.sh
```

首次运行会把 PySide6 6.8+ 隔离安装到 `runtime/a1z-console-python`，不会修改系统
Python 包目录。
也可显式选择初始配置：

```bash
./scripts/run_a1z_console.sh --profile sim
./scripts/run_a1z_console.sh --profile real
```

正常启动控制台时，会自动检查所选 profile 的 ROS 2 栈：节点和 RGB-D
帧均健康时直接复用，缺失节点或相机帧过期时才重新启动。调试控制台本身、
不希望触碰 ROS 运行态时可加 `--no-ros-autostart`；截图和 smoke test
默认不会自动启动 ROS。

逐页视觉回归可使用 `--page`、`--frame`、`--window-size` 和 `--screenshot`，例如：

```bash
QT_QPA_PLATFORM=offscreen ./scripts/run_a1z_console.sh \
  --page manual --manual-section movement --frame tool \
  --window-size 1220x760 --screenshot runtime/manual-movement.png
```

## 安全边界

- 软件急停不能替代现场硬件急停。
- 真机 AnyGrasp 执行不提供“绕过未验证手眼标定”的入口。
- `command_joint_pos` / `command_joint_state` 是高频伺服接口，控制台不会把它们做成
  会产生阶跃的单击按钮；手动运动统一使用带速度约束的 `move_joints`。
- “控制服务在线”不等于“控制循环运行中”；`is_running` 或适配层故障状态异常时，
  运动入口会锁定并在机械臂页给出启动、刷新、重启或切回位置保持的对应恢复动作。
- 电机扫描、夹爪混控测试和零点标定要求先停止 SDK 服务；执行前还会在容器内
  再次确认控制服务进程已经退出，不能仅凭界面显示“离线”推断 CAN 已释放。
  这些操作使用离线设备维护门槛，不要求在线遥测或位置保持；`stale`、身份冲突、
  急停和结果不确定状态仍会闭锁。
- 零点标定必须输入 `校零 A1Z`，且当前姿态会被写入电机零点。
- 软急停发送中、示教录制中、结果不确定或当前 profile 仍被急停锁定时，
  Real/Sim 切换不可用；在线设备还必须先回到机械臂位置保持并关闭夹爪自由拖动；
  遥测处于 stale/checking 时同样不能切换，最后已知的零力/自由拖动状态不会因
  断线而被遗忘；异步回调按 profile generation 校验。结果不确定锁存在时也会
  阻止关闭控制台，避免仅靠重启界面绕过现场确认。
- “停止并保存录制”和“解除软急停”是恢复能力，不要求控制循环仍在运行；
  后端身份、连接与新鲜遥测仍须确认，结果不确定则需先完成上述二阶段核验。

## 页面

- 运行总览：连接、后端身份、控制模式、六轴角度/速度/力矩/温度/故障码。
- 手动操控：按“运动与定位 / 末端工具”组织操作；前者包含模式、关节、
  Base/Tool 点动和预置动作，后者把夹爪模式、目标编辑与物体交互分开。
- 感知检查：RGB/Depth 同步预览、链路状态和相机外参。
- 自动抓取：目标计算、计划安全审阅、dry-run 和显式实际执行。
- 示教与回放：零力示教录制、保存和按后端隔离的轨迹回放。
- 运行配置：控制服务启停和需要重启生效的重力补偿参数。
- 诊断与维护：全链路预检、ROS 管理、硬件能力允许的 CAN 工具和受保护校零。

## RGB-D 预览链路

相机预览不依赖机械臂控制端点。先启动所选 profile 的 ROS 2 栈：

```bash
A1Z_PROFILE=sim ./scripts/run_a1z_ros2_stack_in_container.sh start
A1Z_PROFILE=real ./scripts/run_a1z_ros2_stack_in_container.sh start
```

设备适配器负责发现/独占物理设备或读取仿真相机，随后发布
`A1Z_RGBD_*_TOPIC` 约定。`camera_console_bridge` 将这组主题提供给 GUI：
SIM 使用 `37203`，REAL 使用 `37204`。两个 profile 的端点隔离，且整个 GUI
链路不引用动态变化的 V4L2 节点编号。

真机 profile 将 librealsense 的控制台阈值设为 `fatal`，避免 USB 断开后
底层 V4L2 错误无节流刷屏。ROS 聚合日志采用 64 MiB × 4（当前文件加三个
备份）的轮转上限；相机是否健康仍由相机桥的新鲜 RGB-D 帧状态判断。当前
640×480×30 真机配置还要求 D405 以至少 5,000 Mb/s 的 USB 3.x 链路枚举，
USB 2.0 回退会在启动前直接报错，不再留下“节点存在但无图像”的假健康状态。
